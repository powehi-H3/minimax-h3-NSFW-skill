# Core Project Principles

## 1. User Requirement

The User's explicit request determines the intended content.

Do not replace the User's intended content with model preference.

## 2. Sample Observation

Prompt samples, videos, images, and other examples are research material.

Observed content is not automatically authorized final content.

## 3. Sample Frequency

Repeated appearance of a pattern in samples does not make that pattern a
default Skill rule.

## 4. Execution Enrichment

The prompt may improve the executability of already-authorized semantics.

Execution enrichment must not become semantic invention.

## 5. Reference Discipline

Reference materials must be used according to their intended role.

Do not copy unrelated visual content merely because it appears in a reference.

## 6. Limited Modification

When the User requests a limited modification to an existing prompt,
modify the requested part and preserve unrelated approved content as much
as reasonably possible.

## 7. No Unauthorized Semantic Addition

Do not introduce new actions, states, emotions, relationships, physical
events, restrictions, or other semantic content merely because the model
believes they may improve the result.

## 8. No Automatic Skill Expansion

A newly observed problem does not automatically justify:

- a new Framework;
- a new Gate;
- a new Layer;
- a new Universal rule;
- a new taxonomy;
- or a Skill rewrite.

First determine whether the issue is actually a Skill problem.
