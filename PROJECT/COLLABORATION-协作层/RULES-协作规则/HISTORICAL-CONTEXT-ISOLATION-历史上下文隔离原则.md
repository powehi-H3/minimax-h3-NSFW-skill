# Historical Context Isolation｜历史上下文隔离原则

**Status：ACTIVE / GENERAL COLLABORATION RULE**

适用对象：GPT / Gemini / Grok / 后续加入项目的其他 AI。

---

## 1. 核心原则

> **历史对话可以作为项目背景，但不得在未经当前任务明确授权的情况下，自动成为当前任务的需求、证据、设计依据、优化目标或实验样本。**

“相关”不等于“授权使用”。

AI 不得因为某段历史内容与当前任务看起来高度相关，就自动把它纳入当前任务推理。

---

## 2. 当前任务必须先确定 Input Boundary

开始任何任务前，AI 应先判断：

> **哪些内容被当前任务明确授权为输入？**

只有确定输入边界后，才能开始分析、研究、优化或提出方案。

---

## 3. 三类信息分级

### A. Task Evidence｜本任务证据

可以直接参与当前任务推理：

- 当前任务说明
- 当前任务目录中的指定文件
- 当前任务明确指定的外部资料
- 当前任务明确指定的历史任务 / Prompt
- 当前任务产生的新实验数据
- 用户在当前任务中明确指定“请参考 X”的材料

### B. Project Context｜项目背景

可以用于理解项目，但**不能自动作为当前任务结论依据**：

- 其他任务
- 历史聊天
- 其他任务的 Prompt
- 其他任务的实验结果
- AI 过去形成的工作习惯
- 项目总体背景资料

### C. Historical Reference｜历史参考

历史内容只有在当前任务明确授权后，才能升级为本任务证据。

例如：

> “本次实验请参考 PW-0003 的结果。”

此时 PW-0003 才成为当前任务的 Task Evidence。

---

## 4. 明确禁止的自动推导

AI 不得：

- 因为用户以前做过某类任务，就假设当前任务仍然需要该类能力。
- 因为用户过去喜欢某种 Prompt 写法，就自动把该写法升级为当前任务规则。
- 因为历史任务使用了某个结构，就把它当成当前实验的设计依据。
- 因为历史任务中出现过某种场景、动作或内容，就自动把它带入当前任务。
- 把过去的实验结论自动升级成 Universal Rule。
- 把历史任务中的失败经验自动当成当前任务的已验证事实。
- 用历史聊天补充用户当前没有授权的语义。

---

## 5. 外部 Skill / 外部项目研究任务的特别规则

当任务类型为：

> **“研究 / 对照 / 优化某个外部 GitHub Skill”**

默认必须执行**独立研究**。

研究对象应首先限定为：

1. 当前指定的外部 Skill；
2. 当前任务明确提供的资料；
3. 通用 Prompt Engineering / H3 工程原理；
4. 当前实验产生的数据。

不得把项目历史任务自动变成外部 Skill 的评价依据。

例如：

> “请研究外部 Skill X，并设计独立的 AI Recommended Optimization。”

不得自动解释为：

> “根据我们过去做过的 Prompt 和历史需求来优化 Skill X。”

除非用户明确这样要求。

---

## 6. 实验任务特别规则

对于 A/B、Benchmark、Research Candidate 等实验：

### A 组

必须按照当前任务定义的 A 组输入执行。

### B 组

必须按照当前任务定义的 B 组方法独立推导。

### 禁止

A/B 之间不得因为历史经验而隐式污染。

尤其禁止：

- A 组结果未经授权进入 B 组推理；
- B 组结果未经授权进入 A 组推理；
- 其他历史任务结果自动进入 A/B；
- 历史 Prompt 自动成为 Benchmark 样本；
- 历史用户偏好自动成为评分标准。

---

## 7. 历史资料什么时候可以使用？

只有出现明确授权时才可以。

例如：

- “参考 PW-0003。”
- “把上次那个 Prompt 当作本次实验样本。”
- “根据我们之前的 H3 测试结果调整 B 版。”
- “延续之前确定的角色定义。”

出现这种明确指令后，AI 应把指定材料标记为：

`Task Evidence / Authorized Historical Reference`

并记录其来源。

---

## 8. AI 开始任务前的最小检查

所有 AI 在开始实质工作前，应进行以下内部检查：

```text
CURRENT TASK
    ↓
INPUT BOUNDARY
    ↓
AUTHORIZED EVIDENCE
    ↓
ANALYSIS
    ↓
OUTPUT
```

如果某项信息属于历史内容，但当前任务没有明确授权：

> **只能作为背景理解，不得作为结论依据。**

---

## 9. 对三个核心协作 AI 的统一要求

### GPT

不得因为长期项目上下文而自动把历史需求带入新任务。

### Gemini

作为 Researcher 时，尤其必须区分：

`Task Evidence` 与 `Project Context`。

外部 Skill 研究必须保持独立性。

### Grok

作为 Prompt / 实验执行 AI 时，不得因为过去生成过某类 Prompt，就自动延续其内容或结构。

必须以当前任务提供的需求和实验版本为准。

### 新加入 AI

加入项目后，只需要读取本协作层规则即可理解该原则，无需依赖历史聊天才能知道工作边界。

---

## 10. 与正式 Skill 的关系

本规则属于：

**COLLABORATION LAYER｜协作层**

不是 MiniMax H3 Prompt Skill 的核心生成规则。

因此：

- 不修改 V1-5 Baseline；
- 不属于 Prompt 模板规则；
- 不属于 H3 执行规则；
- 不参与具体 Prompt 的语义生成；
- 只约束多 AI 协作时的信息使用边界。

---

## 11. 一句话版本

> **先确定当前任务允许使用什么，再开始分析；历史上下文默认是背景，不是证据。**

这条规则适用于所有后续任务、所有协作 AI，并可作为新 AI 加入项目时的基础协作纪律。
