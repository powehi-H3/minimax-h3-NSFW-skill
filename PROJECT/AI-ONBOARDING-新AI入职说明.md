# AI-ONBOARDING — 新 AI 入职说明

## 目的

本文件是新加入 H3NSFW-Prompt-Project 的 AI 的第一入口。

加入项目后，先阅读本文件，再依次阅读：

1. `PROJECT/PROJECT-README.md`
2. `PROJECT/COLLABORATION-PROTOCOL-协作协议.md`
3. `PROJECT/ROLE_MATRIX.md`
4. `PROJECT/WORKFLOW-工作流.md`
5. 当前任务目录中的 SOURCE / REVIEW / TEST 文件
6. V1-5 Skill（仅在执行 H3 Prompt 工作时）

## 核心认知

- V1-5 是当前唯一 Frozen Baseline。
- 项目协作协议与 H3 Prompt Skill 是两个不同层级。
- 不因为一次任务中的问题就修改 Skill。
- 不因为一个外部 Skill 有某项机制，就默认加入 V1-5。
- 新 AI 先阅读、理解角色，再开始工作。
- 不覆盖、净化、改写或冒充其他 AI 的 SOURCE / ORIGINAL 原稿。
- Review、Candidate、Draft、Test、Final 必须保持版本和来源可追溯。
- 最终项目决策权属于用户。

## Creative Enhancement 的定义

Creative Enhancement 指的是可选的**剧情 / 叙事 / 镜头创意提升**，不是 Prompt 格式乱加规则。

当用户已经给出明确剧情时，不应擅自改变剧情。
当用户明确要求丰富剧情、增加张力、设计镜头节奏或提供创意方案时，可以进入 Narrative Creative Enhancement 阶段。

## GitHub 写入纪律

任何 AI 都不得把自己的 Review 直接覆盖 SOURCE。

任何项目规则、Skill、STATUS、DECISIONS、CHECKPOINT、ROLE_MATRIX 的修改，都必须遵守项目协作协议和用户授权要求。

## 入职完成标准

新 AI 在开始实际任务前，应能够回答：

- 这个项目是什么？
- 当前 Baseline 是什么？
- 我的角色是什么？
- 我应该读哪些文件？
- 哪些文件属于 SOURCE？
- 我可以修改什么？
- 哪些东西必须经过用户批准？
- Prompt 任务的生命周期是什么？
