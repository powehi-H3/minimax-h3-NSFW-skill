# H3NSFW Prompt Project — DECISIONS

This file records decisions that have already been accepted by the project.

A decision recorded here should not be casually re-litigated in ordinary
Prompt Writing tasks.

---

# D-001 — V1-5 Is the Current Frozen Baseline

Status: APPROVED

Decision:

The current H3NSFW提示词技能skill第三版, internal V1-5 state,
is the current project baseline.

Consequence:

Do not modify the baseline unless the User explicitly approves a change.

---

# D-002 — Practical Prompt Work Has Priority

Status: APPROVED

Decision:

The primary purpose of this project is practical MiniMax H3 prompt writing
and optimization.

Architecture research must not automatically displace normal Prompt work.

---

# D-003 — Official Rules Have Highest Structural Priority

Status: APPROVED

Decision:

When official MiniMax H3 documentation explicitly defines a structure,
field, reference responsibility, syntax, or mechanism, the project follows
that official rule.

Official example content must be distinguished from official mechanism.

---

# D-004 — Sample Frequency Does Not Create a Default

Status: APPROVED

Decision:

A pattern appearing repeatedly in prompt samples does not automatically
become a Skill default.

Evidence must be evaluated separately.

---

# D-005 — Samples Are Not Automatically User Requirements

Status: APPROVED

Decision:

Observed content in an image, video, prompt sample, or other reference
material is not automatically part of the final prompt.

Only content supported by the User's request, approved rules, or justified
execution requirements may enter the final prompt.

---

# D-006 — Execution Enrichment Is Not Semantic Invention

Status: APPROVED

Decision:

The prompt may improve the clarity and executability of authorized content.

It must not use "better execution" as a justification for introducing
new semantic content.

---

# D-007 — Limited Prompt Changes Should Stay Limited

Status: APPROVED

Decision:

When the User requests a specific change to an existing prompt, the change
should remain limited to the requested dimension unless the User authorizes
broader rewriting.

Unrelated approved content should be preserved.

---

# D-008 — No Automatic Framework Expansion

Status: APPROVED

Decision:

A newly observed problem does not automatically justify creating a new
Framework, Gate, Layer, Universal rule, taxonomy, or similar abstraction.

First determine whether the existing Skill already covers the issue.

---

# D-009 — Research Findings Are Not Skill Rules

Status: APPROVED

Decision:

Research observations, community techniques, model inferences, and
experimental findings remain research material until explicitly promoted.

Candidate ≠ Rule.

Experiment result ≠ Rule.

Recommendation ≠ Rule.

---

# D-010 — User Is Final Authority

Status: APPROVED

Decision:

Only the User may approve:

- baseline changes;
- Skill changes;
- promotion of research into project rules;
- final experimental direction.

GPT, Grok, and Gemini are reviewers / researchers / executors according
to their assigned roles.

---

# D-011 — Current Restart

Status: APPROVED

Decision:

The project is considered restarted from the current V1-5 baseline.

Historical architecture discussions are retained as archive/context only
unless explicitly reactivated by the User.

Current work should not automatically reopen historical V1-6 or other
previous candidates.
